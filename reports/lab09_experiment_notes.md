# ЛР9 — короткі нотатки до вимірювання

**Дата:** 10.11.2026  
**Набір:** 100 000 синтетичних завдань, seed 42.  
**Команда:** `python -m task_manager.main profile --count 100000 --workers 4`

Фактичні значення збережено в `lab09_performance_report.json`.

| Реалізація CPU kernel | Час, с | Speedup |
|---|---:|---:|
| Sequential | 0.616 | 1.00× |
| ThreadPoolExecutor | 1.807 | 0.34× |
| ProcessPoolExecutor | 1.644 | 0.37× |

ThreadPoolExecutor не дав виграшу для CPU-bound Python-коду через GIL та overhead потоків. У цьому вимірі ProcessPoolExecutor також програв через створення процесів, pickle/IPC і недостатньо велику вартість одиничної роботи. Це не означає, що multiprocessing завжди повільніший: результат залежить від розміру задачі та вартості передачі даних.

Для повторного dashboard-запиту на тому самому незмінному наборі:

- без кешу: приблизно 30.70 ms/виклик;
- із кешем: приблизно 0.00013 ms/виклик;
- виміряний коефіцієнт: приблизно 233 000×.

Кеш invalidation реалізований у `TaskService` після створення, редагування, зміни status/priority/assignee та видалення завдання. Значення часу machine-specific; вони призначені для демонстрації методики, а не як універсальні нормативи.
